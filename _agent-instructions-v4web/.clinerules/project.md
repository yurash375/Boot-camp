# Правила Cline для проекта v4web (Java + PostgreSQL)

Основные соглашения — в `AGENTS.md` в корне проекта, выполняй их вместе с этими правилами.

## Режим работы

- Задачи на несколько файлов: сначала план (Plan mode), потом правки.
- Правь только то, что требует задача: не переформатируй файлы, не меняй импорты и версии Java
  «заодно», не удаляй чужой код без необходимости.
- Перед правкой найди аналогичный класс в проекте и повтори его стиль.

## Границы изменений

- Только после явного согласования: `pom.xml` (зависимости и версии), `spring.jpa.hibernate.ddl-auto`,
  параметры пула соединений, `.env*`, `application-prod*.yml`, `*.jks`/`*.p12`.
- Уже применённые миграции Flyway (`src/main/resources/db/migration`) не редактировать —
  изменение схемы только новым файлом `V<версия>__<описание>.sql`.
- Не редактировать `target/`, `build/`, `.mvn/**`, сгенерированный код.
- Новые зависимости — только после согласования.

## Проверка результата

- После правок: `mvnw.cmd -q test` (или конкретный класс: `mvnw.cmd -q test -Dtest=SomeTest`).
- Если проверить нельзя — прямо скажи об этом и объясни, как проверить вручную.
- В итоговом ответе перечисляй изменённые файлы и результат сборки/тестов.

## Git

- Работаю в ветке `cline/<id>`; в основную ветку напрямую не коммитить.
- Коммит и push — только по явной просьбе.
- Сообщения коммитов короткие, латиницей: `feat(module): ...`, `fix: ...`, `chore: ...`.
- Секреты, ключи и токены в репозиторий не попадают никогда.
