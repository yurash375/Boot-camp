# AGENTS.md — платформа v4web

Постоянные инструкции для AI-агентов (Cline, GitHub Copilot, Codex, Claude), работающих с этим
репозиторием. Проект расположен в `D:\Work\Yura\v4web\platform`.

## О проекте

- Стек: Java 17+, Spring Boot 3.x, Maven, БД PostgreSQL.
- Сборка: `mvnw.cmd clean package` (в Linux/CI — `./mvnw clean package`).
- Локальный запуск: `mvnw.cmd spring-boot:run` или `java -jar target\platform.jar`.
- Тесты: `mvnw.cmd test`; один тест: `mvnw.cmd test -Dtest=SomeTest#someMethod`.
- Конфигурация: `src/main/resources/application*.yml`; личные переопределения —
  `application-local.yml`, в репозиторий не коммитится.

## Соглашения по коду

- Java Code Conventions: `PascalCase` для классов, `camelCase` для методов и полей,
  `UPPER_SNAKE_CASE` для констант; пакеты только строчными буквами.
- Комментарии и Javadoc — по-русски, идентификаторы — латиницей.
- Использовать только то API, которое доступно в целевой версии Java из `pom.xml`.
- DTO — неизменяемые (`record`); поля классов закрытые; для «может отсутствовать» возвращать
  `Optional`, а не `null`.
- Логирование через SLF4J (`log.info(...)`), не через `System.out.println`.
- Ошибки: доменные исключения + обработка в `@ControllerAdvice`; пустой `catch` запрещён.
- SQL — параметризованный (JPA/`NamedParameterJdbcTemplate`), без склейки строк.

## База данных (PostgreSQL)

- Схема БД меняется только миграциями Flyway: `src/main/resources/db/migration`.
- Имя миграции: `V<версия>__<краткое_описание>.sql`, например `V12__add_user_email_index.sql`.
  Версия — следующий свободный номер, файлы не переиспользуются.
- Уже применённые миграции не редактируются и не удаляются: изменение схемы — только новым файлом.
- `spring.jpa.hibernate.ddl-auto` не менять (`validate`/`none`); автосоздание таблиц запрещено.
- Для существующих таблиц используй `IF NOT EXISTS` / `IF EXISTS`, чтобы миграция была идемпотентной.
- Типы: `timestamptz` для времени, `bigint`/`serial` для идентификаторов, `numeric` для денег
  (`double` не использовать). Строки — `text` или `varchar(n)` с явным ограничением.
- Индексы создавай в той же миграции, что и таблицу или колонку, под которую они нужны.
- Интеграционные тесты — на Testcontainers (`postgresql`), без общей внешней базы; схему готовь
  теми же миграциями Flyway.
- Единственное изменение вне миграций — локальная отладочная база: правки только в
  `application-local.yml`, в репозиторий не попадают.

## Без явного согласования не делать

- Менять зависимости и версии в `pom.xml`, особенно `spring-boot-starter-parent`.
- Менять настройки БД: `ddl-auto`, параметры пула соединений, URL/учётные данные в конфигах.
- Править уже применённые миграции (Flyway/Liquibase) — только добавлять новые файлы.
- Изменять `.env*`, `application-prod*.yml`, хранилища ключей (`*.jks`, `*.p12`).
- Редактировать сборку и сгенерированный код: `target/`, `build/`, `.mvn/**`.
- Переформатировать файл целиком: правь только то, что требует задача.

## Тесты

- JUnit 5 + AssertJ/Mockito; `@SpringBootTest` — только для интеграционных тестов.
- Без `Thread.sleep`; ожидания — через Awaitility или таймауты `CompletableFuture`.
- Имя теста описывает поведение: `shouldRejectExpiredToken()`.
- Новая логика — новый тест; при изменении поведения обновляй существующий.

## Рабочий процесс

1. Перед правкой найди аналогичный класс в проекте и повтори его стиль.
2. Задачи на несколько файлов: сначала план, потом изменения.
3. После правок запусти `mvnw.cmd -q test` (или объясни, почему не смог) и перечисли изменённые файлы.
4. Коммиты короткие, латиницей: `feat(module): ...`, `fix: ...`, `chore: ...`.

## Формат ответов

- Общение — по-русски; код, идентификаторы и имена файлов — латиницей.
- Если требование неоднозначно — задать вопрос, а не додумывать.
